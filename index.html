Stacked Pull Requests

Ship in small reviewable pieces — without waiting.

…and let Copilot CLI do the branch plumbing.

The problem

  • Feature = schema + service + API + tests
  • One PR: 1,400 lines → "LGTM 👍" (nobody read it)
  • Split into 3 PRs off main → PR 2 can't compile without PR 1
  • So you wait. Review latency × 3.

The idea

main
 └─ demo/1-schema  → PR #1 (base: main)
    └─ demo/2-service → PR #2 (base: demo/1-schema)
       └─ demo/3-api   → PR #3 (base: demo/2-service)

Each PR's base is the branch below it →
each PR shows only its own diff.

Why bother

One big PRStack
Review size1400 lines~150 each
Author blocked?yes, until mergeno, keep stacking
Bisect / revertall-or-nothingper layer
Cost—rebase chain on feedback

Demo 1 — build the stack

Create a throwaway private repo stacked-pr-demo, clone it, and build a 3-PR stack for a fake price feature: branch demo/1-schema (schema.sql) based on main, demo/2-service (service.java) based on demo/1-schema, demo/3-api (controller.java) based on demo/2-service. Push each and open a PR with gh pr create -B <parent branch>, titled "1/3 …", "2/3 …", "3/3 …". Print the 3 PR URLs.

…what it actually runs


gh repo create stacked-pr-demo --private --clone && cd stacked-pr-demo
echo "# demo" > README.md
git add -A && git commit -m "init" && git push -u origin main

git checkout -b demo/1-schema
echo "CREATE TABLE price(id int primary key);" > schema.sql
git add -A && git commit -m "add price schema"
git push -u origin demo/1-schema
gh pr create -B main -H demo/1-schema -t "1/3 price schema" -b "Base: main"

git checkout -b demo/2-service           # branches off 1-schema
echo "class PriceService {}" > service.java
git add -A && git commit -m "add price service"
git push -u origin demo/2-service
gh pr create -B demo/1-schema -H demo/2-service -t "2/3 price service" -b "Base: #1"

git checkout -b demo/3-api               # branches off 2-service
echo "@RestController class PriceController {}" > controller.java
git add -A && git commit -m "add price API"
git push -u origin demo/3-api
gh pr create -B demo/2-service -H demo/3-api -t "3/3 price API" -b "Base: #2"

The only trick: -B <parent branch>.

Demo 3 — feedback on the bottom PR

The one real cost of stacking.

Simulate review feedback on PR #1: add a NOT NULL column to schema.sql, commit and push to demo/1-schema, then restack demo/2-service and demo/3-api on top with git rebase + git push --force-with-lease. Show me the commands as you run them. 

git checkout demo/1-schema
echo "ALTER TABLE price ADD COLUMN gross numeric NOT NULL;" >> schema.sql
git commit -am "review: gross not null" && git push

# restack, bottom-up
git rebase demo/1-schema demo/2-service
git push --force-with-lease
git rebase demo/2-service demo/3-api
git push --force-with-lease

Always --force-with-lease, never bare --force.

Demo 4 — merge cascade

Merge PR #1 with squash, then show the base branch of PRs #2 and #3 so I can demo GitHub's auto-retargeting. Then merge #2, re-check #3, then merge #3. 

gh pr merge 1 --squash --delete-branch
gh pr view 2 --json baseRefName   # -> "main"   ← GitHub retargeted it
gh pr merge 2 --squash --delete-branch
gh pr view 3 --json baseRefName   # -> "main"
gh pr merge 3 --squash --delete-branch

Merge bottom-up. GitHub retargets the child automatically — no manual base editing.

Rules of thumb

  • Merge bottom-up, always.
  • Number your titles 1/3, 2/3, 3/3 and link the parent in the body.
  • Keep the stack ≤ 3–4 deep. Deeper = rebase pain > review win.
  • Rebase, don't merge, when restacking.
  • Squash-merge keeps main readable.

Cleanup

Delete the stacked-pr-demo repo and the local clone.

gh repo delete stacked-pr-demo --yes && cd .. && rm -rf stacked-pr-demo

Takeaway

Stacked PRs = small reviews without blocking yourself.

Plain git + gh is enough — the only new flag is gh pr create -B <parent>.

Copilot CLI handles the branch/rebase plumbing so you can stay on the feature.
